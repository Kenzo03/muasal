## Architecture

**Release workflow** (`.github/workflows/release.yml`), run on a tag `v*`:
- **images:** for each of `app` and `web`, buildx with QEMU builds linux/amd64 and linux/arm64. It pushes to `ghcr.io/<owner>/muasal-<component>:<version>` and `:latest` with an SBOM and max-mode provenance, then signs the digest with `cosign sign` (Sigstore keyless, GitHub OIDC).
- **release:** assembles three things:
  - the offline bundle from the amd64 images (`deploy/make-bundle.sh`);
  - `muasal-deploy-<version>.tar.gz`, the deploy files for online installs;
  - `SHA256SUMS`, signed with `cosign sign-blob --bundle`.

  Then `gh release create` attaches them with generated notes.

**Images:**
- The Go stage of `server/Dockerfile` runs on `$BUILDPLATFORM` and cross-compiles with `GOOS` and `GOARCH`, so only the web image needs emulation.
- `compose.yaml` names images `${IMAGE_PREFIX:-muasal}-app` and `-web`. Local builds and the offline bundle keep `muasal`.

**Online install:**
- `install.sh --online` needs a release's `VERSION` and pulls from `ghcr.io/kenzo03/muasal`, or from `MUASAL_IMAGES`.
- With `cosign` installed, it verifies both images against the release workflow's identity before starting anything, and stops on a bad signature.
- It writes `IMAGE_PREFIX` into `.env`.

**Documentation site:**
- `mkdocs.yml` uses Material, with MkDocs pinned below 2, whose rewrite drops Material's theme and plugins.
- It has a new home page and a user guide, alongside the hardware guide, operations, the pilot kit and the ASVS review. The plans are excluded.
- `.github/workflows/docs.yml` builds with `--strict` on pull requests that touch the docs, and deploys to GitHub Pages from `main`.

**Contribution guide:** `CONTRIBUTING.md` covers:
- setup, and the repository layout;
- the rules: visibility in SQL, tests, both languages, untrusted model output, no outbound calls, licences, style;
- pull requests, licensing (inbound = outbound) and releases.

The README and `SECURITY.md` link the release and its verification.

## Deliberate Deviations from the FSD

- **The offline bundle is amd64 only.** Its `images.tar` holds one platform, and arm64 servers install online from the signed GHCR images.
- **`upgrade.sh`** still upgrades from a bundle. An online upgrade is `docker compose pull` with the new `VERSION` in `.env`, as the operations guide says for rollbacks.
- **Documentation language:** the site is in English. The app itself ships in Indonesian and English.
- **Outside the repository:** the trademark search (§22.2), claiming the npm name and domains, turning on GitHub Pages ("GitHub Actions" as the source), and the first `v*` tag are the maintainers' steps.
